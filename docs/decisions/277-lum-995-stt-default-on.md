## Context

Thomas decided on 2026-11-18 that a clean install from the two Release files has voice straight away (LUM-995). Three gaps stood in the way:
- The Release `docker-compose.yml`, generated by `scripts/release/build_release_compose.py`, carried no speech-to-text.
- Speaches 0.8.3, the sidecar pinned in `docker-compose.stt.yml`, never installs a model on its own. Its `DEFAULT_MODEL` setting does not exist in 0.8.3, so every transcription got a sidecar `404` and an app `503`.
- Web showed every failure only in a tooltip, which phones never display.

ADR 031 named in-process `faster-whisper` as the default STT path and the HTTP sidecar as an alternate. The in-process adapter (LUM-45) was never built.

## Decision

The Release compose carries `lumogis-stt` (Speaches 0.8.3, the same digest as the checkout overlay, native amd64 and arm64) under a new **`stt` Compose profile**. The release `example.env` switches it on with `COMPOSE_PROFILES=stt` and `STT_BACKEND=whisper_sidecar`. A household turns it off by removing `stt` from `COMPOSE_PROFILES`, setting `STT_BACKEND=none`, and stopping and removing the `lumogis-stt` container by name (`docker compose stop` + `rm -f`, as the graph Turn off does). A service in an inactive profile is not an orphan, so `up -d --remove-orphans` leaves it running.

**Core installs the speech model itself:**
- At start-up it makes one non-blocking attempt.
- A retry job repeats it with backoff.
- A transcription that hits a missing model starts the install on demand.

Each install is `GET` / `POST /v1/models/{STT_MODEL}` on the sidecar, single-flight. Its state shows in admin diagnostics.

Failures reach Lumogis Web as typed codes (`stt_disabled`, `stt_model_missing`, `stt_unreachable`). The dictation button shows them as visible text, and it shows "Listening…" with a level meter while recording.

Checkouts keep STT opt-in through the overlay. The sidecar, not in-process `faster-whisper`, is now the shipped default topology on the `SpeechToText` port.

## Alternatives Considered

Full detail: `.cursor/explorations/LUM-995-stt_default_on.md`.
- **Unprofiled Release service:** there is no household-level off switch, and upgraders would get an 850 MB pull.
- **STT in the base `docker-compose.yml`:** every checkout and CI stack would pay for it.
- **One-shot `lumogis-stt-init` compose service:** it does not heal a volume reset until the next `up`, and it cannot tell the button why transcription failed.
- **Wrapping the Speaches entrypoint:** inline shell that copies Speaches internals.
- **Speaches 0.9.0-rc.3 `PRELOAD_MODELS`:** a release candidate, and it exits when a download fails, so it crash-loops on an offline first start.
- **A Lumogis-published image with the model baked in:** a sixth published, attested image for an offline benefit nobody has asked for.
- **Browser Web Speech API:** cloud-backed on iOS, already rejected by ADR 031.
- **An Admin one-click switch:** Thomas chose on by default instead.

## Consequences

**Easier:**
- Voice works on a clean Release install on amd64 and arm64: on the install computer at `http://localhost`, and on phones and other computers once Admin → Secure address is on. Browsers give the microphone only to a secure context, and the default `CADDY_DOMAIN=:80` is plain HTTP; there the button says so instead of disappearing.
- A volume reset heals itself.
- The household sees why dictation failed.
- The checkout overlay's model install works too, so `.env.example` becomes true.
- Optional Release components now have one shape: a profile listed in `COMPOSE_PROFILES`, edited with `list_with` / `list_without`.

**Harder:**
- The Release ships a third-party runtime image by default. Bumping the Speaches digest is release hygiene, and the release smoke (LUM-997) must cover voice.
- A Release install costs more RAM and disk. Measured on amd64 (Pass 0): the engine image is about 0.85 GB to download and 3.04 GB on disk, the model about 280 MB, so about 3.3 GB in all; about 0.6 GB of RAM with the model loaded, 452 MB idle after the unload. Thomas accepted the disk cost on 2026-11-18; the quickstart states it. arm64 numbers are an owner proof still open.
- The sidecar contacts Hugging Face: to download the model, and to list and check models when it starts and when it first loads the model after a restart (model ids only, never audio). It is the first third-party contact a default install makes. `HF_HUB_DISABLE_TELEMETRY=1` is set (and enforced by the release `check()`), and `TELEMETRY.md` lists the contact. `HF_HUB_OFFLINE=1` is not set: it would block the install itself.

**Future chunks must know:**
- `/health` on Speaches is 200 without a model, so readiness is `GET /v1/models/{id}`.
- `POST /v1/models/{id}` on an installed model answered **200** in Pass 0 (the draft said 201); Core treats 200 and 201 alike and confirms every `POST` with a `GET` (Speaches #587).
- `lumogis_stt_models` is never mounted into `backup`, so the model is not backed up; it can be downloaded again.
- Existing installs are not switched on by an update.
- LUM-45 (in-process `faster-whisper`) is an alternative, not the default.

## Revisit conditions

- **Speaches ships a stable 0.9.x with `preload_models`** that does not exit on a failed download: consider dropping Core's start-up install and keeping only the on-demand 404 path.
- **Speaches has no commit for 12 months, or a CVE goes unpatched in the pinned image:** re-evaluate the engine (whisper.cpp server, or LUM-45 in-process).
- **Measured idle RAM of the sidecar exceeds about 500 MB on arm64,** or households report it as a reason to turn it off: consider lazy start (stack-control starts `lumogis-stt` on first use).
- **Offline or air-gapped installs become a requirement:** revisit the baked-model image.
- **Non-English households report bad transcripts with `base.en`:** switch the default to multilingual `Systran/faster-whisper-base`.

## As built (2026-11-18, /verify-plan)

The decision shipped as written. Deviations from the plan, each with intent kept:

- **Narrow 404 rule.** Pass 0 showed Speaches 0.8.3's 404 bodies differ: an uninstalled model answers `Model '…' is not installed locally…`, an unknown route answers `Not Found`. Only the first maps to `SttModelMissing` (`_MODEL_NOT_INSTALLED_MARKER` in `adapters/whisper_sidecar_stt.py`); any other 404 is `stt_processing_error`. The `stt_404_with_model_installed` warning stays as a safety net.
- **Disk go/no-go restated** by Thomas: "download ≤ 1.5 GB; disk use stated in the quickstart" (the plan's 1.5 GB line had read the compressed image size as disk).
- **Miss bookkeeping.** `services/stt_model_readiness.py` snapshots the miss counter and consumes the pending-miss flag right before each deciding `GET`, and clears the flag on a failed outcome, so a click during the first download is not reported as a wrong transcribe path.
- **`model_installed` maps every timeout** (not only connect errors) to `SttUnreachable`: an engine too busy to answer a cheap `GET` is "not answering", never a timed-out download.
- **Web status text** lives in one `role="status"` region that stays mounted, so screen readers announce each change.

Proven: backend unit and route tests, release-generator tests, Vitest, and a live amd64 run against the real Speaches digest. Core installed the model with no manual step, and it reinstalled the model after a volume reset without a restart. **Not yet proven:** arm64 numbers, a clean install from release-candidate files, dictation on a phone at the secure address, the turn-off and graph toggle by hand, and the Playwright spec `voice_dictation_status.spec.ts` against a stack running this build. These are owner proofs, tracked as a `gate:pre-main` child of LUM-995.
