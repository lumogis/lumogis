## Context

LUM-104 adds real-world temporal validity and LLM contradiction detection to the premium FalkorDB knowledge graph. ADR-150 (LUM-558) fixed the direction: build clean-room on the existing KG layer, borrowing Graphiti's four-timestamp schema and contradiction semantics as reference detail only — no vendoring, no imports, no pip dependency. The shipped substrate is ADR-133's single-axis Postgres `valid_until` recall contract (authoritative and untouched), ADR-015's single household graph with scope-column union, ADR-138's per-bank graphs, and ADR-042's export boundary (`GRAPH_MODE` default `disabled`). Plan: `.cursor/plans/archived/LUM-104-temporal-validity.plan.md` (hardened through self-review ×2, external critique, arbitration; three checkpoint decisions ratified 2026-07-02).

## Decision

1. **Four-timestamp schema** on `RELATES_TO` / `MENTIONS` / `DISCUSSED_IN` edges: `created_at` (ingestion time, stamped once), `valid_at` (real-world truth time), `invalid_at` (superseded), `expired_at` (reserved for purge/expiry) — plus `edge_uid` (stable invalidation/SUPERSEDES target; app-side uuid4, never generated in Cypher) and strictly increment-only `contradiction_count` (LUM-369's stability signal; recurrence never resets it). Storage is the fixed `%Y-%m-%dT%H:%M:%SZ` UTC format so lexicographic comparison in Cypher is chronologically correct; **everything passes through `to_graph_ts()` / `parse_graph_ts()`** (`services/lumogis-graph/graph/temporal.py`) — legacy `_now_iso()` values (variable width, microseconds, offset) are never copied raw (the backfill normalises app-side). FalkorDB NULL is property **absence**; no sentinel strings. `DERIVED_FROM` excluded (no validity window). Single-current-interval rule **R1**: a MERGE'd pair edge holds one current interval; recurrence after invalidation rewrites `valid_at` forward and removes `invalid_at` (self-heal); multi-interval history per edge rejected for v1 — history lives in the SUPERSEDES structure.
2. **LLM stages live Core-side only** (`orchestrator/plugins/graph/temporal_pipeline.py`), preserving the KG-service invariant ("KG never invokes an LLM"): the graph receives only data — computed `valid_at` values and invalidation instructions executed by the LLM-free mechanics in `graph/temporal.py`. v1 is scoped to `GRAPH_MODE=inprocess`; service-mode parity is a revisit note (file only when the split-service topology ships — checkpoint register resolution, no ticket now).
3. **Contradiction detection is background**, never inline: a deferred hook stage after projection (same ingest events, `fire_background` executor) plus an hourly newest-first sweep keyed on the `temporal_checked_at` evidence-node stamp (statuses: `ok | extract_failed | judge_failed | text_unavailable | skipped | backfill` — one enum, defined once, shared Core/KG-side by test). No ongoing ingest path skips detection; only the explicit historical backfill does (stamps `backfill` without LLM calls).
4. **Model tiers:** small local tier for `valid_at` extraction (fail-safe: any failure → ingestion-time default; future values clamped), the **eval-reference judge class** for contradiction judgment. Checkpoint decision (a): auto-apply is hard-pinned to the reference judge model class (default key `llama3.1:8b`) — the eval bar is measured against one named reference model and does **not** transfer; a household on a different judge stays in shadow mode. Cloud is never the default; `get_llm_provider` inherits the LUM-194 privacy gates and LUM-125 circuit breaker.
5. **Auto-apply gated by the hand-graded eval** (`orchestrator/tests/premium/temporal_eval/`): precision(supersedes) ≥ 0.90 AND Wilson 95% lower bound ≥ 0.70 AND ≥ 20 expected-supersedes rows (the runner refuses a gating verdict below the floor). Below the bar: shadow mode — `applied: false` SUPERSEDES proposals only. Checkpoint decision (b): **v1 ships stamping + read-side validity filtering + shadow proposals; auto-apply is conditional and may never enable; shadow output is not user-visible in v1.** Guards G1–G8 enforced and test-pinned, notably G1: auto-apply candidates are personal-scope-only; shared-scope contradictions are **detected and recorded** as `scope: "shared"` proposals (ADR-147 represent-both inherited), never applied.
6. **SUPERSEDES representation:** evidence-node→evidence-node edge (edge-to-edge is impossible in a property graph) carrying `{invalidated_edge_uid, edge_type, entity_pair, at, applied, confidence, user_id[, scope]}`, MERGE-keyed on the invalidated edge's uid (idempotent sweep retries), plus invalidation audit properties on the superseded edge (`invalid_at`, `invalidated_by_evidence_id`, `invalidation_reason` — LLM free-text, **untrusted-on-display**). The superseded-side node resolves via the pair's most recent co-mention episode in `entity_relations`; unresolvable targets fall back to edge properties only. Memory→Memory retarget planned when LUM-528 lands; purge (`DETACH DELETE` of evidence nodes) deletes incident SUPERSEDES edges by design (privacy-first; the invalidated edge stays invalid).
7. **ADR-133 relationship (additive; not reopened)** + the Lumogis-owned sync invariant: graph `invalid_at` set ⇒ the judged `entity_edges` rows' `valid_until` set **in the same operation, Postgres first** — row-scoped to exactly the `(src, dst, relation_type)` tuples whose fact text the judge saw. On graph-write failure after Postgres success, the evidence node stays unstamped so the sweep re-drives the episode (retry idempotent via the `valid_until IS NULL` guard); recall reads Postgres and is already correct.
8. **Accepted approximations:** backfilled `valid_at` = normalised `last_seen_at` proxy (honest but coarse); co-occurrence-only edges are never judged (guard G2 — no fact text is the over-invalidation trap); residual prompt-injection blast radius bounded by G1–G8 (worst case: soft-invalidating the same user's own personal edges, capped, self-healing); one-way sync asymmetry — a Postgres archive does not invalidate `RELATES_TO` co-occurrence edges (provenance, not the fact; typed projections already purged by LUM-544; revisit if hint/recall divergence confuses in practice — checkpoint decision (c)); `shortest_path` interior edges are not validity-filtered (`algo.SPpaths` exposes no edge-predicate seam — same accepted posture as the documented interior scope-check deferral); DOCUMENT episodes hydrate `text_unavailable` in v1 (no Postgres text source for document bodies). **Archiving principle:** Lumogis never destroys memories — contradiction handling archives a fact as no-longer-current (sets `invalid_at`, retains full SUPERSEDES history, R1 self-heals); it never deletes; forgetting is a deliberate user act (LUM-544), never a side effect of contradiction detection (restates guard G7 + the no-`DELETE` grep gate, not a new mechanism).
9. **Revisit conditions:** the eval shows local models cannot reach the bar (re-open the model-tier / Graphiti-reference question per ADR-150); FalkorDB gains native temporal or cross-graph features; LUM-528/LUM-369 land and need richer interval history; hint/recall divergence from the one-way sync asymmetry proves confusing in practice.

## Consequences

**Easier:** contradictions become auditable, reversible archive events with an in-graph review surface (SUPERSEDES, including shadow proposals) and no new Postgres tables; LUM-528 and LUM-369 get a stable property contract (`schema.py` temporal constants, fixed timestamp format, `edge_uid` semantics, re-projection rule: Postgres is truth — archived row ⇒ edge keeps/gains `invalid_at`; active row + invalid edge ⇒ genuine recurrence, R1 reset). The entity-merge transfer fix (full property map + RELATES_TO MERGE-by-pair) removes a pre-existing lossiness and a resurrection hazard independent of the flag.

**Harder / owned:** contradiction-judgment quality on local models is Lumogis-owned (the eval gate is the control); the Postgres-first sync invariant and the fixed-format timestamp discipline must hold across every future writer of temporal properties (grep gates + byte-identity pins enforce this); the flag-on-before-backfill window costs at most one sweep batch per hour against recent episodes until `POST /graph/backfill/temporal` runs (enablement runbook: flag on, then trigger backfill).

**Rollout:** Stage 0 (shipped): `LUMOGIS_FF_TEMPORAL_KG` off — zero behaviour change, byte-identical write/read Cypher (test-pinned kill switch). Stage 1: flag on — stamping + backfill + read filtering + shadow detection. Stage 2: auto-apply — permitted recommendation only after a committed eval report meets the bar on the reference judge model; per-household enablement stays operator-explicit.
