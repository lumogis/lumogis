## 3. What changed, by feature

### LUM-212 — Skeleton / loading primitives
**New:** `src/features/_shared/Skeleton.tsx` (+ `.module.css`) — `Skeleton`, `SkeletonText`,
and an accessible `LoadingPlaceholder` (single `role="status"` + `aria-busy` region with an
sr-only label; shimmer blocks are `aria-hidden`; reduced-motion aware via `src/design/tokens.css`).
**Wired into:** `DocumentsPage` (skeleton table), `AdminAuditView` (dense rows),
`ChatPage` (typing-dots indicator before first token), `EntityCard`/`EntityCardPanel` (entity detail).
**Not built yet (primitive ready for reuse when they land):** entity browser (LUM-161),
Today surface (LUM-111), a server-backed capture list.

### LUM-211 — Error states + boundary
**New:** `src/features/_shared/ErrorState.tsx` (+ `.module.css`) — `role="alert"`, plain-language
message, **never** raw 500/stack/JSON, default Retry action, optional `lumogis doctor` hint
(composes `EmptyState` for button styling). `src/components/AppErrorBoundary.tsx` — class boundary
catching render crashes → friendly fallback (Try again / Reload).
**Wired into:** document library, audit log, entity detail error branches (with Retry → refetch/reload).
**App.tsx:** two boundaries — an **outer** one (last-resort for shell/nav crashes) and an **inner**
one around `<Routes>` (keeps nav usable when only a page crashes).

### LUM-512 — Service health + degradation banners
**Backend (new):**
- `orchestrator/routes/api_v1/health.py` — `GET /api/v1/health`, `dependencies=[Depends(require_user)]`
  (authed, **non-admin**), mounted via the `api_v1` aggregator.
- `orchestrator/services/user_health.py` — projects the stack-status snapshot to a **whitelisted,
  non-sensitive** `{overall, services}` DTO and caches it (serve-stale-while-revalidate, ~10s TTL).
- `orchestrator/services/stack_status.py` — new `build_service_states()` (compose probe + store
  pings only; **skips** the storage `statvfs` scan + Ollama model-list HTTP the admin snapshot does).
- `orchestrator/models/api_v1.py` — `HealthResponse` model.

**Frontend (new):** `src/api/health.ts` (`fetchHealth`), `src/features/_shared/useServiceHealth.ts`
(react-query poll ~20s + per-service `isOllamaDown/isQdrantDown/isGraphDown` + stable `refresh()`),
`src/features/_shared/ServiceDegradationBanner.tsx` (+ `.module.css`).
**Wired into `ChatPage`:** banner above the transcript; **`refreshHealth()` is called on chat error
paths** (`!res.ok`, stream error, network catch) so the request — the source of truth — reconciles
the banner immediately rather than waiting for the poll.

**Degradation model (intentional):**
- **Ollama down** → hard-fail `role="alert"` ("Local AI unavailable… messages may fail").
  > Send is **not yet disabled** (LUM-194-gated) — copy deliberately says "messages may fail", not "paused".
- **Qdrant down** → degraded `role="status"` ("Document search unavailable — using knowledge graph only").
- **Graph (KG store) down** → degraded `role="status"` ("Knowledge graph temporarily unavailable").
- `unknown`/`degraded`/`not_configured` states are treated as **not down** (no false-alarm banner);
  only a definitive `"down"` triggers a banner.

### LUM-420 — chat sidebar mobile smoke
`tests/e2e/chat-sidebar-mobile.spec.ts` — pins the `.lumogis-chat` grid collapse (260px+1fr → 1 col)
at a phone viewport, with a desktop counter-check. On-stack (see §6).

## 4. New API contract — `GET /api/v1/health`

- **Auth:** `require_user` (any authenticated user; 401 if unauthenticated). **Not** admin-gated.
- **Response (`HealthResponse`):**
  ```json
  { "overall": "ok|degraded|down",
    "services": { "ollama": "healthy|degraded|down|unknown|not_configured",
                  "qdrant": "...", "graph": "..." } }
  ```
- **Whitelist:** only `{ollama, qdrant, graph}` are exposed (the 3 ids the client reads). The full
  internal topology (caddy, mongodb, librechat, stack_control, postgres, orchestrator, …) is **withheld**
  from non-admins. Free-text `message`, `runtime_detail`, storage, and the model list are dropped.
- **Cache:** process-global, serve-stale-while-revalidate, ~10s TTL. Data is stack-wide (no per-user
  content) → safe to share. `services.user_health.reset_cache()` is a test hook.
- **OpenAPI:** `clients/lumogis-web/openapi.snapshot.json` is committed and up to date. The generated
  TS types (`src/api/generated/openapi.d.ts`) are **gitignored** — regenerate with `npm run codegen`.

## 7. Known limitations / explicitly out of scope

- Send is **not** disabled when Ollama is down (LUM-194 privacy-mode gates the cloud-fallback decision);
  banner copy reflects this ("messages may fail", not "paused").
- The orchestrator does not yet emit a `degraded` retrieval marker / actually fall back to KG-only or
  vector-only — the **UI is ready** but the server behaviour is a deferred LUM-512 item.
- `AppErrorBoundary` "Try again" remounts the subtree (good for transient crashes); a deterministic
  render error re-shows the fallback — "Reload" is the hard reset. By design.
- LUM-511 surfaces (ingest stage bar, transcription poll, batch counter) are **not** built — they need
  backend work first (see the LUM-511 comment).
